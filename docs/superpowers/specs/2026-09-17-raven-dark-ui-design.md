# Raven dark UI — 디자인 제안

상태: 사용자 승인 후 구현 및 검증 완료. 기본 다크 테마에 적용한 디자인 기준.

## 방향

토스의 명확한 정보 전달과 일관된 컴포넌트 원칙을 Raven에 적용한다.
사용자 지정 조건은 다크 테마, Spotify 그린 포인트, 둥근 버튼과 창이다.
아래 색상·크기·레이아웃 수치는 Raven용 제안이며 토스 공식 규격이 아니다.

## 조사 근거

- [토스 라이팅 원칙](https://toss.tech/article/8-writing-principles-of-toss): 핵심 메시지에 집중하고 불필요한 표현을 줄이며 다음 동작을 예상할 수 있게 안내한다.
- [앱인토스 UX 라이팅](https://developers-apps-in-toss.toss.im/design/ux-writing.html): 한국어 문구에는 해요체와 능동형 표현을 사용한다.
- [TDS Colors](https://tossmini-docs.toss.im/tds-mobile/foundation/colors/): 배경·레이어·떠 있는 요소의 색상 역할을 구분한다. 공개 페이지의 밝은 팔레트를 다크모드 규격으로 해석하지 않는다.
- [토스 디자인 시스템](https://toss.tech/article/toss-design-system): 공통 컴포넌트에서 다크모드, 긴 텍스트, 접근성을 함께 다룬다.
- [Spotify 디자인 가이드](https://developer.spotify.com/documentation/design): 그린을 브랜드 식별 색으로 사용하며 충분한 대비를 강조한다.

## 접근 방식

| 방식 | 범위 | 판단 |
| --- | --- | --- |
| 공통 스타일만 교체 | 색상·모서리 변경 | 빠르지만 정보 위계와 화면 밀도 개선이 부족함 |
| 공통 스타일 + 화면별 정보 위계 정리 | 전 화면 색상·여백·타이포·버튼·카드·폼 | 권장. Raven의 표와 빠른 입력을 유지하며 일관된 경험 제공 |
| 내비게이션과 모든 흐름 재설계 | 메뉴 이동과 입력 단계까지 변경 | 이번 시각 개선보다 범위가 크고 재학습 필요 |

| 역할 | 제안 값 | 사용 |

| 전체 배경 | `#121212` | 앱 캔버스 |

| 높은 표면 | `#28282B` | 모달·드롭다운 |

| 보조 텍스트 | `#B0B0B8` | 설명·레이블 |
| 포인트 | `#1ED760` | 주요 CTA·선택 표시·핵심 그래프 |
| 포인트 위 텍스트 | `#121212` | 그린 버튼의 레이블 |

| 구분선 | `#38383D` | 표 행·섹션 경계 |
| 입력 경계 | `#777780` | 입력 영역 식별 |

그린은 주요 행동과 선택에 집중한다. 오류·주의는 독립된 의미 색을 사용한다.
상태와 차트는 색뿐 아니라 텍스트·아이콘·선 패턴으로도 구분한다.
`color-scheme: dark`를 적용해 기본 날짜 입력과 select도 테마에 맞춘다.

## 형태·여백·타이포그래피

- 버튼·입력창: 반경 14px, 기본 높이 44–48px.
- 카드: 반경 20px. 모달: 24px. 드롭다운: 16px. 태그: pill.
- 표는 바깥 컨테이너를 둥글게 하고 셀 정렬과 정보 밀도를 유지한다.
- 카드 내부 여백 24px, 모바일 16–20px. 섹션 간격 24–32px.
- 페이지 제목 28–32px/700, 카드 제목 18–20px/600, 본문 15–16px.
- 핵심 숫자 32–40px, 금액·날짜는 tabular 숫자로 정렬한다.
- 기존 sans-serif 계열을 재사용하고 한국어 시스템 글꼴 fallback을 명시한다.
- 상태 전환은 120–180ms로 짧게 한다. reduced-motion을 존중한다.

## 화면 적용

| 화면 | 적용 기준 |
| --- | --- |
| 공통 내비게이션 | 둥근 활성 메뉴, 은은한 그린 배경과 명확한 선택 표시 |
| Dashboard | 핵심 숫자를 먼저 읽게 배치하고 제목·설명·차트의 시각적 강도를 구분 |
| ToDo | 표·캘린더 정렬 유지, 완료·선택·hover 구분, 도구 버튼의 위계 통일 |
| Ledger | 금액의 크기와 정렬 강조, 거래 표·요약 카드·차트의 표면 통일 |
| Health Journal | 기록 폼의 간격과 레이블 정돈, 선택 태그·보고서·히트맵의 다크 대비 확보 |
| 모달·드롭다운 | 높은 표면과 둥근 모서리, 분명한 제목·주요 행동·닫기 버튼 |

현재 까마귀 로고는 몸체가 어두워 다크 배경에서 대비를 점검한다.
필요하면 로고 영역에 의도적인 밝은 원형 배지를 사용하고, 사각형 흰 배경이 남지 않게 한다.

## 문구

현재 영어 UI는 언어를 유지하면서 짧고 구체적인 행동명으로 정돈한다.
예: 맥락 없는 `Add`보다 `Add meal`, 모호한 `OK`보다 `Save changes`.
한국어가 필요한 곳은 친근한 해요체를 사용하되 전면 번역은 별도 결정이다.
오류는 문제와 복구 행동을 함께 안내하며 저장 실패 시 입력값을 유지한다.

## 구현 연결

- `frontend/src/design/tokens.ts`와 `frontend/src/styles/globals.css`의 색상·모서리 기준을 동기화한다.
- 색 이름에 묶인 기존 토큰 사용처를 확인하고 배경·텍스트·액션 역할에 맞춰 매핑한다. 검정과 흰색의 단순 치환은 피한다.
- 전역 CSS의 직접 지정된 색·반경 및 inline 차트 색상을 함께 점검한다.
- 공통 버튼·필드·모달 규칙을 먼저 적용하고 화면별 밀도와 타이포를 조정한다.
- 다크모드가 기본 테마다. 별도 테마 전환 기능은 이번 범위에 포함하지 않는다.
- 기존 TagsInput의 fixed portal, 모달 포커스 격리, Escape·Tab 동작을 보존한다.
- 모달 조상에 fixed 기준점을 바꾸는 transform/filter를 적용하지 않아 드롭다운 잘림을 방지한다.
- 새 UI 프레임워크 없이 기존 컴포넌트와 CSS를 사용한다.

## 완료 확인 기준

- Dashboard·ToDo·Ledger·Health·설정·모달에 밝은 배경이나 읽기 어려운 글자가 남지 않는다.
- 일반 텍스트 대비 4.5:1, 큰 글자와 필수 UI 식별 요소 대비 3:1을 확인한다.
- 버튼의 hover·pressed·disabled·focus-visible 상태를 구분한다.
- 390px 모바일과 1440px 데스크톱에서 표·긴 제목·긴 태그를 확인한다.
- 짧은 뷰포트에서 모달 스크롤, 태그 검색·선택, 달력·메뉴 경계 잘림을 확인한다.
- 키보드만으로 모달 열기·입력·저장·닫기가 가능하고 닫은 뒤 포커스가 복구된다.
- 기존 기능 테스트, 타입 검사, 정적 빌드와 대표 화면 브라우저 검증을 통과한다.
- 검증 데이터는 임시 데이터만 사용한다.
